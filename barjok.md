## 🚦 ПРАВИЛА: что трогать, а что нет

> Этот раздел — первое, что нужно прочитать перед любой правкой. Каждый пункт здесь
> появился ПОСЛЕ реальной поломки, а не из общих соображений. Ссылки на разборы — в
> разделах «Свежие изменения» ниже.

### 🔴 НЕ ТРОГАТЬ без явной причины (тут уже ломали)

| Что | Почему нельзя | Что будет, если тронуть |
|---|---|---|
| **CSS `zoom`/`transform` для масштабирования на `/map/`** | Leaflet/MapLibre считают клики в реальных пикселях | Клики по карте «промахиваются» мимо пинов. Для масштаба есть `--fs` (см. ниже) |
| **Порядок `rewrites` в `vercel.json`** | `/:city/` и `/:city/:service/` матчат ЛЮБОЙ 1–2-сегментный путь | Catch-all 404 в конце перестанет срабатывать / сломается роутинг города |
| **`'unsafe-inline'` в CSP** | На сайте десятки инлайновых `<script>`/`<style>` без nonce | Сайт «побелеет»: отвалятся инлайновые обработчики. Убирать только вместе с nonce-рефактором |
| **Ресурсные ключи в `api/_lib/i18n-kk.js`** | Приходят в `dk()` ДИНАМИЧЕСКИ (`RES_TABS`, `RES_LABEL_NOM`) | Grep по `dk('...')` их не находит → выглядят «неиспользуемыми» → удаляются → KZ-версия молча уезжает в русский |
| **`git checkout --ours/--theirs` при конфликте `map/data.json` в rebase** | При rebase семантика ОБРАТНАЯ привычной | Данные откатываются на старую логику незаметно. Правильно — перегенерировать: `node parser/index.js pavlodar` |
| **Демо-данные `pavlodar-curated.js`** | Это аварийный фолбэк, не источник | Нарушение 🔒-правила: на проде появятся выдуманные отключения |

### 🟡 ТРОГАТЬ ТОЛЬКО ПАРАМИ (иначе копии разъедутся)

| Файл | Парный файл | Почему разделены |
|---|---|---|
| `landing/shared.css` | **`/shared.css` (корень)** | В проде раздаётся КОРНЕВОЙ. Правка только `landing/` не доезжает до пользователей. После правки: `cp landing/shared.css shared.css` |
| `buildCsel` в `api/_lib/admin-layout.js` | `buildCsel` в `map/index.html` | Карта — статический HTML без шаблонизатора, `require` невозможен. Копии уже дважды расходились |
| `loadPendingReports()` | `pendingFilter()` в `api/admin-api.js` | Чтение и отклонение обязаны видеть одинаковый набор строк, иначе админ гасит невидимые ему голоса |
| `--fs` autoscale в `seo-layout.js` | `--fs` в `map/index.html` | Разные пороги (760px / 900px) — это НЕ ошибка, а разные раскладки. Формулу менять в обоих |
| `MAX_ACTORS_PER_IP_OUTAGE` в `decision-engine.js` | одноимённая в `api/admin-api.js` | Админка показывает голоса тем же правилом, что считает движок. Разошлись → владелец ждёт автоподтверждения, которое не наступит |

### 🟢 ОБЯЗАТЕЛЬНО ДЕЛАТЬ

1. **Правил `map/styles.css` или `map/app.js` → подними `?v=` у ЭТОГО файла** в `map/index.html`.
   Кэш `max-age=86400`: без бампа пользователи сутки получают старый файл, а `curl` с
   query-параметром это маскирует. Версии у файлов независимые — бампать нужно только изменённый.
   Правки в самом `map/index.html` бампа не требуют (HTML без длинного кэша).
2. **Новый источник данных → сначала строка в 🔒-реестр, потом код.** Без записи парсер не подключать.
3. **Регулярки по русскому тексту — только явные классы `[а-яё]`.** `\w` и `\b` в JS
   НЕ работают с кириллицей: `/горяч\w*/` не матчит «горячую», источник молча отсеивается.
4. **Иконка + текст в одном элементе → `data-kk` на внутренний `<span>` с текстом.**
   На родителе `el.textContent = ...` сотрёт `<svg>` вместе с текстом.
5. **Публичный эндпоинт → rate-limit со СВОИМ `name`.** Origin-проверка ботов НЕ
   останавливает (заголовок подделывается любым скриптом), см. `api/_lib/security.js`.
   Общий `name` = общее ведро: реклама съедала квоту жалоб и ломала приём заявок.
6. **Адрес клиента — только через `ipHash()`/`clientIp()`, НИКОГДА не
   `x-forwarded-for[0]`.** Это цепочка, куда прокси дописывают адреса: первый элемент
   выбирает сам отправитель, и на нём любой лимит обходится сменой префикса.
7. **Защита не должна отказывать в опасную сторону.** Прежде чем ограничить действие,
   проверь, что будет, если оно НЕ произойдёт: потолок голосов на восстановление намертво
   запирал ложное отключение на карте — это хуже, чем то, от чего он защищал.

### 📌 Ограничения платформы (не обойти, только учитывать)

- **Vercel Hobby: максимум 12 serverless-функций.** Сейчас занято 11. Новый маршрут добавлять
  НЕ отдельным файлом, а веткой в существующем (`api/pages.js?page=...`, `api/admin-api.js`).
- **Заголовки в `vercel.json` матчатся по ВХОДЯЩЕМУ пути, не по цели rewrite.** `/admin/` → `/api/admin`
  не получает правил от `/api/(.*)` — для него нужен свой блок.
- **Проект без npm/бандлера.** Никаких `package.json` и импортов из npm: только голые
  serverless-функции и vanilla JS. Библиотеки — вручную в `map/vendor/`.

## 🔒 РЕЕСТР ИСТОЧНИКОВ ДАННЫХ — ГЛАВНОЕ ПРАВИЛО (нельзя нарушать)

> Проект масштабируется на другие города и пригороды Казахстана. Чтобы не было путаницы,
> **каждый источник данных фиксируется здесь ДО написания парсера.** Это правило обязательно.

**Правила (не нарушать):**
1. **Только официальные источники поставщиков** (энерго/водоканал/теплосети/газ городов). Никаких
   выдуманных, демо- или «примерных» данных в проде. `pavlodar-curated.js` — только аварийный фолбэк, НЕ домешивать.
2. **Новый город/пригород добавляется в таком порядке:** (а) внести все его источники в таблицу ниже
   (система · URL · формат · метод · adapter · статус) → (б) написать адаптер `parser/adapters/<city>-*.js` →
   (в) зарегистрировать город в `parser/cities.js`. Без записи в реестр — парсер не подключать.
3. **Каждая запись реестра указывает:** какую СИСТЕМУ покрывает (электро / холодная вода / горячая вода /
   отопление / газ), точный URL, формат (docx / html-новости / API / картинка-OCR), метод парсинга,
   файл-адаптер и статус (✅ работает / ⚠️ частично / ❌ нет источника).
4. **Данные привязываются к конкретным домам** (разворот улиц в дома через OSM-реестр), с bounds-фильтром
   по городу. Сельские/пригородные адреса из «районных» файлов отсекаются, если не относятся к покрываемому городу.

сознательно не реализован, см. шапку `decision-engine.js`) — событийный

cron-инфраструктуры (лимит 12 функций Vercel Hobby). Когда срок истёк —
`status→RESTORED`, `manual_override→NONE` (control возвращается автоматике,
Decision Engine снова может сам реагировать на голоса жителей по этому
адресу — не просто «гасит на экране»).

Дата показана в таблице админки: `manual_override_until` → «Восстановится
DD.MM HH:MM» рядом с бейджем ручного режима.

## Свежие изменения (v30) — фиксы мобильной шторки карты

Два бага с реальных скриншотов пользователя:

1. **Кнопка доступности (`#a11y-widget`) наезжала на карточки списка.**
   Виджет — `position:fixed`, `z-index:900`. Когда шторка (`.sheet`) раскрыта
   почти на весь экран (класс `.expanded`, JS в `map/app.js`), карточки
   списка занимают низ экрана — ровно там же, где висит кнопка. Сама `.sheet`
   имеет z-index:18 (ниже виджета) — не перекрывает её, поэтому нужно было
   прятать явно. Фикс — чистый CSS без правок JS:
   `body:has(.sheet.expanded) #a11y-widget { opacity: 0; pointer-events: none; }`
   внутри `@media (max-width: 900px)`. `.report-fab` той же проблемой не
   страдает — у неё z-index:17, ниже `.sheet` (18), поэтому и так прячется
   позади шторки автоматически.
2. **Поиска не было внутри шторки** (был только вверху топбара — неудобно
   тянуться, когда шторка раскрыта). Добавлена третья копия поиска
   (`#searchSheet`/`#suggestSheet`/`#clearSearchSheet`, тот же паттерн
   `mini-search search`, что уже был у десктопной версии в `.panel`) внутри
   `.sheet`, между `.filterbar` и списком. Зарегистрирована в `SEARCHES[]`
   (`map/app.js`) — значение синхронизируется живьём между всеми копиями
   через уже существующий `input`-listener (`setSearchValue()`), отдельной
   логики не потребовалось. `.mini-search{display:none}` на мобильном был
   общим для ЛЮБОЙ копии — сужен до `.panel .mini-search` (десктопная версия
   и так недостижима, `.panel{display:none}` на этой ширине), новая копия
   внутри `.sheet` остаётся видимой.

- Фолбэк (нет `navigator.share` — почти все десктопы): `navigator.clipboard.
  writeText()` копирует тот же текст, тост подтверждает копирование. Ошибка
  (например, запрет доступа к буферу) — отдельный тост, ничего не ломает.
- Ссылка — `https://barjok.kz/map/pavlodar?q=<адрес>` (или `/kz/map/pavlodar`
  при казахском интерфейсе) — уже существующий параметр `?q=`, при открытии
  сам находит и открывает карточку этого адреса (см. `load()`).
- ⚠️⚠️ Ссылка ВСЕГДА встроена ПРЯМО В ТЕКСТ — отдельного поля `url` в
  `navigator.share()` НЕТ (было, убрано после живого теста). `navigator.
  share({url})` резолвит переданную строку через собственный класс `URL`
  ДО передачи в систему и percent-encode'ит кириллицу НЕЗАВИСИМО от того,
  что было на входе — на реальном устройстве получатель в WhatsApp видел
  `.../?q=%D0%91%D0%BE%D1%82%D0%BA%D0%B8%D0%BD%D0%B0...`, хотя ссылка
  собиралась через читаемый `shareEncode()`. Строка внутри `text` —
  простой текст, никто её не резолвит: WhatsApp/Telegram сами линкуют её
  по регулярке при показе и percent-encode'ят уже на стороне получателя,
  когда он реально открывает ссылку — сам текст остаётся читаемым.
- `shareEncode()` кодирует только то, что ломает URL как текст (пробел, `%`,
  `?`, `#`, `&`), кириллицу оставляет как есть — вместо нечитаемой простыни
  от `encodeURIComponent()`. «Сырой» Unicode в URL валиден (IRI) и корректно
  открывается в любом браузере при переходе — тот же приём, что у сайтов
  с кириллическими доменами.
- Текст сообщения начинается с адреса (`📍 {адрес}` первой строкой) — получатель
  сразу видит, что это про конкретный дом, а не общий анонс по улице/району.
- Кнопка показывается, только если есть что реально сообщить (хотя бы одно
  отключение); в ветке «по адресу всё в порядке» (`openAddressCard`) её нет.

## Свежие изменения (v27) — отдельные `/kz/...` SSR-страницы вместо клиентского тоггла

Раньше казахский язык был чисто клиентским переключателем (`applyLang()`,
`data-kk`/`localStorage`) — поисковик всегда видел русский HTML, отдельного
проиндексированного казахского URL физически не существовало. Теперь `/kz/{city}/`
и `/kz/{city}/{service}/` — настоящие серверно отрендеренные страницы.

**Архитектура — «выпечка» (bake), а не рефактор рендера.** RU-страница строится
БЕЗ ИЗМЕНЕНИЙ, как раньше (`seo-blocks.js`/`seo-cards.js` не тронуты вообще, кроме
двух точечных исключений ниже). Для `/kz/...` тот же готовый HTML один раз, на
сервере, прогоняется через новую **`api/_lib/bake-kk.js`** (`bakeKk(html)`) — она
делает regex-проходом то же самое, что клиентский `applyLang('kk')` делает в
браузере: `data-kk="..."` → текст, `data-kk-html="..."` → HTML с тегами (`<b>`),
`data-kk-ph="..."` → `placeholder`. Безопасно только потому, что в проекте уже
жёсткое правило — `data-kk` ставится ТОЛЬКО на элемент, целиком состоящий из
текста (иконка — всегда отдельный `<span>`).

**Что bake НЕ покрывает (правилось вручную):**
- `<title>`/`<meta description>` — не видимый DOM, `data-kk` там никогда не было.
  Казахские title/h1/description — в новом `SERVICE_META_KK` (`api/_lib/seo.js`),
  переведены вручную для всех 8 услуг.
- `<html lang>` (`kk` вместо `ru-KZ`) и hreflang (`ru`/`kk`/`x-default`, раньше не
  было нигде в проекте — grep подтвердил) — `api/_lib/seo-layout.js`.
- Внутренние `href` в `navHtml()`/`footerHtml()` — параметр `lang` добавлен ТОЛЬКО
  для префикса `/kz`, весь текст остался RU+`data-kk` (единый механизм перевода,
  не два параллельных).
- Кнопка KZ/RU в шапке — раньше JS-тоггл без перехода, теперь настоящая
  `<a href="/kz/{city}/...">` — то, ради чего вся задача.

⚠️ **Узкое исключение для `seo-blocks.js`/`seo-cards.js`:** `bakeKk()` не трогает
generic `href`, поэтому `serviceTilesHtml()` и `groupedOutagesHtml()` получили
опциональный параметр `lang` **строго для префикса `/kz` на ссылках** (`/map/...`,
`/{city}/{service}/`) — вся остальная логика перевода (`dk()`) в этих файлах не
менялась.

⚠️ **Порядок `rewrites` в `vercel.json` (см. правило выше про `/:city/`)** — новые
`/kz/`, `/kz/map/`, `/kz/:city/`, `/kz/:city/:service/` стоят СТРОГО ПЕРЕД `/:city/`
и `/:city/:service/`, иначе `/kz/pavlodar/` матчился бы как `city=kz`.

`/kz/map/` и `/kz/map/pavlodar` — простые alias-rewrite на тот же статический
`map/index.html` (карта остаётся 100% клиентской, свой отдельный `[data-t]`/`t()`
словарь). Единственная правка — `map/app.js`: начальный `LANG` теперь смотрит
на префикс `/kz/` в пути, если в `localStorage` ещё нет явного выбора.

`renderSitemap` — добавлены `/kz/{city}/` и `/kz/{city}/{service}/` рядом с
RU-версиями. `/kz/about/` — осознанно не сделан (было решено отложить).

## Свежие изменения (v26) — защита эндпоинтов, админки и данных

Аудит всех публичных входов + укрепление админки. Новый общий модуль
**`api/_lib/security.js`** (origin-allowlist, хэш IP, rate-limit).

### 1. ⚠️⚠️ Закрыта дыра: разрешался ЛЮБОЙ чужой `*.vercel.app`

`originOk()` был скопирован в `api/report.js` и `api/_lib/ads-tracking.js`, и **в обеих
копиях** стояло `/\.vercel\.app$/`. Любой человек деплоит свою страницу на vercel.app и
постит к нам с неё — origin-проверка не значила ничего. Теперь список закрытый: прод-домены
+ `VERCEL_URL` текущего деплоя (чтобы свои preview-деплои работали) + опциональный
`ALLOWED_ORIGINS` из env. Обе копии заменены на общий модуль.

### 2. Rate-limit на публичных эндпоинтах (раньше не было вообще)

- `/api/report` — 5 за 10 мин и 20 за час на IP (в памяти) + **суточный durable-потолок
  40** по `user_reports.ip_hash` (память лямбды не переживает холодный старт; отдельной
  таблицы не заводили — жалобы и так пишутся в БД). Лимит стоит ДО работы, чтобы флуд не жёг
  ни Telegram, ни квоту Supabase.
- `/api/ads-track` — 60/мин и 600/час. Превышение НЕ отдаёт ошибку (§75: трекинг не ломает
  UX), просто не пишет событие: иначе накруткой показов/кликов можно исказить frequency cap,
  лимиты кампании и отчёт рекламодателю.
- `/api/ads-select` — 30/мин и 300/час. Единственный из трёх, кто ходит в Supabase
  БЕЗУСЛОВНО на каждый запрос: без лимита циклом на curl сжигалась бы квота БД и бюджет
  вызовов. (Пропущен в первой версии — найдено ревью.)

⚠️⚠️ **`name` в `rateLimit(name, key, windows)` обязателен, и вот почему.** В первой версии
ключ строился только из IP и длины окна — а у `/api/report` и `/api/ads-track` совпадало
часовое окно (3600000). В итоге они делили ОДНО ведро: ~25 событий трекинга рекламы за
обычный визит съедали часовую квоту жалоб, и живой человек получал **429 на первой же
жалобе об отключении** — ломалась главная функция сервиса. Найдено ревью до деплоя.
Добавлять новый лимит — всегда со своим `name`.

⚠️ **`hit()` не дописывает метку, когда уже за лимитом.** Иначе флуд рос бы в памяти без
предела (час × сотни rps = миллионы чисел в одном ключе) и каждый запрос фильтровал бы
этот массив — лимитер жёг бы ресурсы ровно на том трафике, ради которого стоит.
`Retry-After` при этом считается до истечения самой старой метки, а не как целое окно.

### 3. ⚠️⚠️ Определение IP: `x-forwarded-for[0]` — подделывается клиентом

Самая опасная находка ревью этой версии. `X-Forwarded-For` — это **цепочка**, куда
прокси ДОПИСЫВАЮТ адреса. Если клиент сам пришлёт `X-Forwarded-For: 1.2.3.4`, а edge
допишет реальный адрес в конец, то `split(',')[0]` вернёт **значение, выбранное
атакующим**. На этом ключе построены И rate-limit, И потолок голосов на IP — то есть,
меняя поддельный префикс на каждом запросе, атакующий обходил бы обе защиты полностью.

Исправлено в `clientIp()`: сначала `x-vercel-forwarded-for`/`x-real-ip` (их ставит сама
инфраструктура Vercel и перезаписывает клиентские одноимённые), затем **ПОСЛЕДНИЙ**
элемент XFF (тот, что дописал наш прокси, а не тот, что придумал клиент), затем сокет.
Проверено тестом: три запроса с разными поддельными префиксами дают ОДИН ключ.

**Правило на будущее: никогда не брать `x-forwarded-for[0]` как адрес клиента.**

Там же закрыты два обхода помельче:
- пустой ключ больше не означает «пропустить лимит» (не опознали клиента → общее ведро
  `anon`), иначе достаточно было прийти без опознаваемого IP;
- при переполнении карты счётчиков вытесняются самые старые ключи, а не `clear()` всей
  карты — иначе переполнение намеренным мусором **обнуляло бы счётчик самому атакующему**.

### 4. ⚠️ Закрыта накрутка голосов Decision Engine — но ТОЛЬКО в сторону отключения

`actor_key` — это cookie. Очистил → «новый житель». Порог 3 добирался **в одиночку**, и на
публичной карте появлялось несуществующее отключение. Введён
`MAX_ACTORS_PER_IP_OUTAGE = 2` в `currentVotes()`: с одного `ip_hash` засчитываются
максимум 2 разных actor_key. Записи без `ip_hash` (старые) считаются как раньше.

⚠️⚠️ **Первая версия применяла потолок к ОБОИМ направлениям — и это был отказ в опасную
сторону.** В Павлодаре дом обычно сидит за одним CGNAT провайдера: потолок 2 при
`restoreThreshold = 3` означал, что отключение, однажды поставленное (вручную админом или
импортом), **никогда не снимется автоматически** — сколько бы жильцов ни нажало «Уже
появилось». Карта бессрочно показывала бы «нет воды» там, где вода есть, и сама себя не
чинила. Найдено ревью, исправлено: потолок только на OUTAGE.

**Асимметрия сознательная, по цене ошибки:**
- ложное ОТКЛЮЧЕНИЕ — активная ложь на карте, её и защищаем потолком;
- ложное ВОССТАНОВЛЕНИЕ самокорректируется: ресурса нет — жильцы пожалуются снова.

Там же по итогам ревью:
- **Потолок считается ПО НАПРАВЛЕНИЯМ раздельно.** Иначе голоса противоположного
  направления «съедали» лимит IP и молча резали то направление, которое сейчас проверяется.
- **`else restore++` → `else if (state === 'RESTORED')`.** Любой мусор в колонке
  (`null`, пустая строка) раньше считался голосом ЗА закрытие инцидента.
- **Админка показывала другую цифру, чем движок:** `loadPendingReports` считал сырые
  `actor_key` без потолка → строка «3 сообщения» выглядела готовой к автоподтверждению,
  которое не могло наступить. Теперь `votes` считается тем же правилом, а рядом отдаётся
  `raw_votes`, и в UI при расхождении подписано «часть с одного IP — не в счёт».

### 5. Вход в админку

- Самописное посимвольное сравнение пароля заменено на `crypto.timingSafeEqual` по
  SHA-256-дайджестам: прежнее сравнение делало ранний `return false` при разной длине
  (**утечка длины пароля по времени ответа**) и в JS всё равно не было константным.
- Добавлен тормоз перебора: 10 промахов за 5 мин / 40 за час на IP → `429 Retry-After`.
  **Считаются только НЕудачные попытки** — браузер владельца шлёт корректный заголовок на
  каждый запрос админки, и общий счётчик запирал бы его самого (проверено тестом).

### 6. Заголовки: `/admin` их не получал

Заголовки в Vercel матчатся по **входящему** пути, а `/admin/` переписывается в `/api/admin`
уже после — то есть правило `/api/(.*)` с `no-store`/`noindex` до админки **не доходило**, и
её страницы отдавались кэшируемыми и индексируемыми. Добавлены свои блоки для
`/admin(/.*)?` (`no-store, private`, `noindex, nofollow, noarchive`, `X-Frame-Options: DENY`,
`Referrer-Policy: no-referrer`) и для `/report(/.*)?` (публичные отчёты по токену — чтобы
токен не утекал в `Referer` при переходе по внешним ссылкам). `robots.txt` дополнен
`Disallow` — с явной пометкой, что это просьба, а не защита.

По итогам ревью там же:
- ⚠️ **`X-Frame-Options: DENY` на `/admin` был инертен.** Глобальный CSP с
  `frame-ancestors 'self'` перекрывает XFO во всех современных браузерах, то есть админка
  оставалась встраиваемой в iframe с любой страницы своего же домена. Добавлен отдельный
  CSP для `/admin` с `frame-ancestors 'none'` (правила ниже перекрывают одноимённые
  заголовки выше).
- ⚠️ **`originOk` для GET держался только на `Referer`.** Браузер не шлёт `Origin` у
  GET/HEAD, поэтому `/api/ads-select` проверялся по `Referer` — а его вырезают Brave,
  uBlock и режимы приватности: такие пользователи получали 403 на ровном месте, при том
  что от бота `Referer` не защищает (один флаг curl). Теперь первым проверяется
  `Sec-Fetch-Site` — это «запрещённое имя заголовка», его ставит сам браузер и подделать
  из JS нельзя.
- ⚠️ **429 в админке теперь всё равно отдаёт `WWW-Authenticate`.** Без него браузер не
  показывает диалог входа, а первый запрос сессии всегда идёт БЕЗ заголовка и считается
  промахом — владелец с общего IP (офис/коворкинг), где кто-то сжёг лимит, не увидел бы
  ни формы, ни способа ввести пароль.

📌 **Проверить curl'ом после деплоя** (весь блок держится на том, что Vercel СЛИВАЕТ
совпавшие правила, а не берёт первое):
```bash
curl -sI https://barjok.kz/admin/ | grep -i 'cache-control\|x-robots\|content-security'
```

⚠️ **Пояснения к этим блокам живут ЗДЕСЬ, а не в `vercel.json`:** JSON не поддерживает
комментарии, а Vercel валидирует файл строго — попытка положить ключ-комментарий `"//"`
внутрь элемента `headers[]` даёт «should NOT have additional properties» и **роняет весь
деплой**. Проверено при написании этой версии: ключи убраны. В `vercel.json` разрешены
только `source`/`headers`/`has`/`missing`.

### Что осталось сознательно НЕ сделано

- **CSP всё ещё с `'unsafe-inline'`** — на сайте десятки инлайновых скриптов, полный переход
  на nonce — отдельный рефактор (см. таблицу «не трогать»).
- **Rate-limit в памяти не общий между инстансами лямбды** — durable-слой есть только у
  `/api/report`. Для остального хватает: цель — не дать потоку, а не построить WAF.
- **Нет капчи.** Honeypot + origin + rate-limit покрывают массовый спам; капча ухудшит
  главный сценарий (быстро пожаловаться на отключение), вводить только если спам реально пойдёт.

## Свежие изменения (v25) — KZ-перевод, кастомные селекты, mobile autoscale, админка «Отключения», 404/offline, Analytics, CSP

Большая сессия смешанных доработок — языковая версия сайта, UI-компоненты, админка
и техническая безопасность/наблюдаемость. Ниже — по блокам.

### 1. Полный казахский (KZ) перевод сайта

`data-kk`/`data-kk-html`/`data-kk-ph` — тот же паттерн переключения «на месте»
(без отдельных URL), что уже был на старом лендинге, теперь распространён на ВСЕ
SEO-страницы и живые данные карты. Общий `localStorage` ключ `barjoq_lang`.

- **`api/_lib/i18n-kk.js`** (новый) — словарь RU→KK + `dk(ru)` хелпер, возвращающий
  `data-kk="..."`. Специально дублирует свой `esc()`, а не импортирует его из
  `seo-layout.js` — иначе циклический `require` (seo-layout сам берёт `dk` отсюда).
- `applyLang()` (единый скрипт переключения) встроен в `seo-layout.js`; переведены
  nav/footer/контакты/hero/FAQ/карточки отключений/a11y-виджет.
- ⚠️ **Иконка+текст в одном элементе** — если `data-kk` повесить на родителя с
  `<svg>`-иконкой внутри, `el.textContent=...` при переключении сносит иконку.
  Правило: `data-kk` только на отдельном `<span>`, оборачивающем ТОЛЬКО текст.
- ⚠️ **`data-kk` vs `data-kk-html`** — если RU-текст содержит теги (`<b>${n}</b>`),
  обычный `data-kk` покажет теги буквально. Нужен `data-kk-html` (свап `innerHTML`).
- ⚠️⚠️ **Некритичный `localStorage.getItem` рвал ВЕСЬ скрипт.** И в новом
  `seo-layout.js`, и в старом `map/app.js` было необёрнутое `localStorage.getItem`
  на верхнем уровне скрипта — в браузерах с ограничениями приватности это кидает
  исключение СИНХРОННО, обрывая скрипт ДО навешивания обработчиков кликов (переключатель
  языка молча не работал). Обнаружено случайно через песочницу без localStorage.
  Исправлено try/catch в 4 местах (seo-layout.js×2, map/app.js×2).
- «Живые данные» (текст из парсера) переводятся насколько возможно (лейблы ресурсов,
  статусы, UI-текст карточек); честно объяснено пользователю, что произвольный текст
  причины из источника (`reason`) — не переводится (это не lookup-словарь).

### 2. Кастомный `<select>` (`.csel`) по всему сайту

Пользователь: «нужно сделать селект не системным, а внутренним». Обёртка над нативным
`<select>` (остаётся единственным источником значения, `opacity:0` поверх кастомной
кнопки+меню, реальные `change`-события — код чтения формы не менялся). Реализовано
дважды с одинаковой логикой: светлая тема на `/map/` (репорт-модалка), тёмная —
`api/_lib/admin-layout.js` (общая для всех `/admin/*`).

- ⚠️ **Баг «селекты задваиваются».** `buildCsel()` должен САМ вызывать
  `sel.classList.add('csel-native')` на исходном `<select>` — если положиться на то,
  что класс стоит в разметке, где-то забудут проставить, и нативный select рендерится
  рядом с кастомным (было на всех `/admin/*` страницах). Исправлено в обеих копиях.

### 3. Мобильный autoscale (`--fs`, Tilda-style fluid scale)

Единая CSS-переменная `--fs`, считается один раз при загрузке (375px → 1, 440px →
~1.17, потолок, форс 1 выше брейкпоинта — 760px для SEO-страниц, 900px для `/map/`),
применяется через `calc(Npx * var(--fs,1))`. **Не через CSS `zoom`/`transform`** —
это ломает точность кликов Leaflet/MapLibre (известное ограничение проекта, см. v3
про a11y-виджет). Также прокинута в JS как `window.BARJOK_FS` — маркеры/кластеры на
карте (`pinIcon`/`clusterIcon` в `map/app.js`) масштабируются тем же коэффициентом.

### 4. Админка «Отключения» — статусы, фильтры, CSV, авто-обновление

Полный запрос: статус «Новая», фильтр по ресурсу+городу, колонка города, выгрузка CSV,
починить «новые жалобы не показываются», добавить экраны 404/нет интернета.

- **Корневая причина «новые жалобы не видны»:** админка читала ТОЛЬКО таблицу
  `incidents` (подтверждённые Decision Engine, порог 3 голоса), но НИКОГДА не читала
  `user_reports` (сырые жалобы жителей) — единичная/недостаточная для порога жалоба
  была архитектурно невидима в UI. Добавлен `loadPendingReports()` в `api/admin-api.js`:
  берёт `user_reports` за 14 дней, группирует по адрес+ресурс, исключает те, что уже
  есть в активных `incidents`. Админка рендерит их как строки со статусом **«Новая»**
  (бейдж) + голоса/текст + действия «Подтвердить»/«Отклонить» (последнее — новый POST
  `reject_pending`, ставит `user_reports.status='REJECTED'`).
  Строки «Новая» всегда сортируются первыми.
- Фильтры: ресурс, город (селект + отдельная колонка), статус (дефолт — «все», было
  «только активные» — из-за этого «новых» тоже не было видно).
- **CSV-экспорт** — клиентская генерация Blob/`<a download>`, BOM-префикс для
  корректной кириллицы в Excel.
- `setInterval(load, 60000)` — автообновление раз в минуту (частично покрывает
  сценарий «пришла жалоба, а в админке её нет без ручного релоада»), плюс кнопка
  «Обновить».

### 5. 404 / offline-экраны + фикс роутинга

- **`404.html` как статика НЕ раздаётся** — Vercel сначала прогоняет `rewrites`, а
  `/:city/`/`/:city/:service/` матчат ЛЮБОЙ 1–2-сегментный путь раньше catch-all.
  Настоящий обработчик — `renderNotFound()` в `api/pages.js` (переиспользует
  существующую функцию — на Vercel Hobby лимит 12 serverless-функций, было занято 11).
  Подключён в `renderCity`/`renderService` (было `res.status(404).send('Not found')`)
  + новый catch-all `{ "source": "/(.*)", "destination": "/api/pages?page=notfound" }`
  последним в `vercel.json`.
- `offline.html` — статика, `navigator.onLine`/online-offline листенеры, авто-релоад
  при восстановлении сети.
- Учитывая блэст-радиус (плохой catch-all мог сломать раздачу статики) — сделана
  живая пост-деплой проверка всех статических ассетов и живых маршрутов.

### 6. Vercel Web Analytics

Проект без npm/бандлера (осознанное архитектурное решение) — вместо
`@vercel/analytics/next` (Next.js-инструкция пользователя) подключено vanilla-скриптом
`<script defer src="/_vercel/insights/script.js"></script>` на всех статических/SSR
страницах (лендинг, ads, 404, offline, все SSR-шаблоны через `seo-layout.js`).

### 7. Content-Security-Policy + прочие security-заголовки

X-Content-Type-Options/X-Frame-Options/Referrer-Policy/Permissions-Policy уже стояли —
внешний сканер зачем-то показал «нет» (ложное срабатывание), реально не хватало
только CSP. Собран через полную инвентаризацию доменов (grep всех HTML/JS на литералы
URL + разбор живого `style.json` MapLibre — все тайлы/спрайты/шрифты идут с ОДНОГО
домена `tiles.openfreemap.org`). Финальная директива — см. `vercel.json`. Прагматично
разрешён `'unsafe-inline'` для `script-src`/`style-src` (на сайте десятки инлайновых
`<script>`/`<style>` без nonce-инфраструктуры — полный nonce-рефактор не в этой сессии).
- ⚠️ **Первый деплой ломал Яндекс.Метрику/Webvisor** — `connect-src` не пускал
  `wss://mc.yandex.ru/solid.ws` (только `https://` схема была в списке), `frame-src`
  был `'none'`, а Webvisor открывает iframe. Найдено живой проверкой консоли сразу
  после деплоя. Исправлено: добавлены `wss://`-варианты в `connect-src`, `frame-src`
  → `https://mc.yandex.ru`.
- ⚠️ **Методология живой проверки:** `read_console_messages` браузерного тула может
  показывать УСТАРЕВШИЕ ошибки из более ранних навигаций той же вкладки — не доверять
  ему одному. Достоверно — прямой `fetch(url,{cache:'no-store'})`/`new WebSocket(url)`
  из текущего документа через JS-инструмент.

### 8. Правило «соседних домов» убрано для электричества

Пользователь: плановые отключения электричества официально публикуются точным списком
домов — достраивание «соседних» домов (±3 по номеру, эвристика для одноразового импорта
жалоб ГВС/ХВС из Telegram, `parser/build-manual-reports.js`) могло исказить/«нарушить»
официальный график, если бы когда-нибудь в этот же одноразовый импорт попала жалоба по
электричеству. Проверено: это единственное место во всём кодбейзе, которое реально
достраивает «соседние» дома (остальные грепы на «рядом/соседн/radius» — либо про
геокодинг/реестр домов, либо про `expandStreetRecords` в `parser/index.js`, который
разворачивает УЖЕ заявленную улицу в её собственные дома, а не додумывает соседние).
Исправлено: `resource !== 'electricity'` перед блоком достройки соседей + комментарий
с обоснованием.

### 9. Чистка после ревью (/review по всему диффу сессии)

Прогон ревью по диффу v25 нашёл 8 пунктов, все закрыты:

- ⚠️⚠️ **`reject_pending` гасил больше, чем показывал.** Кнопка «Отклонить» била по
  `address+utility_type+status=VALID` без фильтров, а pending-строка строится из
  `reported_state=OUTAGE` за 14 дней. То есть отклонение мусорной жалобы заодно
  переводило в REJECTED голоса **«Уже появилось» (RESTORED)** по тому же адресу —
  а их считает `decision-engine.js:currentVotes`, чтобы СНЯТЬ отключение. Итог:
  дом мог навсегда залипнуть отключённым на карте. Исправлено: введён общий
  `pendingFilter(address, utility_type)` — один источник правды и для чтения
  (`loadPendingReports`), и для отклонения. **Правило: эти два места держать синхронными.**
- **`.csel` — клавиатура вместо регресса.** Нативный select под кастомным получает
  `tabindex=-1`/`aria-hidden`, но стрелки/Home/End не были воспроизведены — для
  клавиатурного пользователя это был откат по сравнению с обычным select. Дописаны
  ArrowUp/ArrowDown (с перепрыгиванием `disabled` и зацикливанием), Home/End,
  Enter/Space, Escape; подсветка — через класс `.csel-opt.active`, под который CSS
  уже был написан, но никем не проставлялся (мёртвое правило стало живым).
- **Разъезд копий `.csel` устранён.** В карте была обработка `placeholder`, в админке —
  нет. Добавлено в админку (+ CSS `.csel-val.placeholder`). В ОБА файла вписан
  явный парный комментарий-предупреждение.
- **Удалены мёртвые `404.html` и `offline.html`.** Оба физически недостижимы:
  catch-all rewrite перехватывает всё до статики (реальный 404 — `renderNotFound()`
  в `api/pages.js`), а без Service Worker переход без сети до сервера не доходит
  вообще, так что своя офлайн-страница отдаться не может в принципе. Комментарии,
  ссылавшиеся на эти файлы, переписаны, чтобы не отправлять следующего разработчика
  за несуществующим.
- **Убраны мёртвые ключи словаря** `'Плановое'`, `'Аварийное'`, `'ещё улица'`,
  `'ещё улиц'` — ни один путь в `dk()` до них не доходил (у сервисных страниц свои
  `labelKk`, у табов — `RES_TABS`, а фразу с числом собирает `moreLabelKk`).
  ⚠️ Над оставшимися ресурсными ключами стоит предупреждение: они приходят в `dk()`
  ДИНАМИЧЕСКИ, grep по `dk('...')` их не находит — **не удалять как «неиспользуемые»**.
- **`moreLabelKk`: тернарник с двумя одинаковыми ветками** (`n===1?'көше':'көше'`)
  убран — в казахском после числительного существительное не принимает множественное
  число, так что форма тут одна by design. Добавлен комментарий, чтобы это не
  «чинили» обратно.

### 10. Критические баги, найденные и исправленные в этой сессии (не относятся к одной фиче выше)

- ⚠️⚠️ **Раздвоение `shared.css`.** Корневой `/shared.css` (реально раздаётся в проде)
  и `landing/shared.css` — два разных файла, которые нужно держать синхронизированными
  вручную. Как минимум один фикс (`.cbtn .ct .l/.v{display:block}`) молча никогда не
  доехал до прода из-за правки только `landing/`-копии. Обязательное правило на будущее:
  после любой правки `shared.css` — `cp landing/shared.css shared.css`.
- ⚠️⚠️ **Не бампалась версия кэша карты.** `map/styles.css`/`map/app.js` раздаются с
  `Cache-Control: max-age=86400`, версия — в `?v=...` у соответствующего тега в
  `map/index.html`. Несколько правок подряд (позиция a11y-виджета на мобилке, чистка
  mapNotice, `--fs`-автоскейл) не бампали версию — реальные пользователи могли сутками
  получать устаревший JS/CSS, при этом `curl`-проверка с явным query-параметром это
  маскировала. Обязательное правило: бампать версию при КАЖДОЙ правке этих двух файлов.
  📌 **Уточнение (проверено ревью v25):** версии у файлов НЕЗАВИСИМЫЕ, а не единая на
  все теги, как утверждалось раньше — сейчас `styles.css?v=1788300200`,
  `app.js?v=1788300100`, вендоры на `1788300000` (у них `immutable`, бампать не нужно).
  Бампать надо ровно тот файл, который правил. Правки в самом `map/index.html`
  (инлайновые скрипты/разметка) бампа не требуют — HTML отдаётся без длинного кэша.

## Свежие изменения (v24) — мультирегиональное SEO + редизайн SEO-страниц + доступность + IndexNow

Самое крупное расширение с v23 — сайт из «лендинг + карта» стал полноценной
многостраничной SEO-структурой с SSR, плюс два прохода редизайна и техническая
доводка для поисковой индексации.

### 1. City Config → SSR SEO-страницы (§30 SEO-ТЗ, принцип «подключение города = данные, не код»)

`api/_lib/seo-cities.js` — единственный источник правды: `status: 'active'|'soon'`
решает, существуют ли публичные SEO-страницы города (Павлодар — `active`;
Экибастуз/Аксу — `soon`, отдают честный 404, в sitemap не попадают).
Из него автоматически строятся:

- **`/`** — национальный хаб (список городов).
- **`/{city}/`** — страница города: живой статус (снэпшот из `map/data.json`,
  без "fake 0"), поиск с live-подсказками адреса, превью карты, плитки услуг,
  «Текущие/Предстоящие отключения» (сгруппированы по улице+ресурсу, табы-фильтр
  по ресурсу, плитка «+N ещё» вместо тихого обрезания списка при >11 карточек),
  блок «Как начать», FAQ.
- **`/{city}/{service}/`** — 8 сервисных страниц на город (вода/холодная/горячая/
  свет/отопление/плановые/аварийные/по адресу), тот же набор блоков, отфильтрованный
  под ресурс/тип услуги (`api/_lib/seo-cards.js:groupedOutagesHtml`).
- **`/map/`** — селектор города для карты.
- **`/sitemap.xml`** — динамический, строится из `activeCities()` × `SERVICES`
  (не хардкод) — новый активный город появляется в sitemap сам, без правки кода.

Всё живёт в **11 serverless-функциях** (Vercel Hobby, лимит 12) — SEO-страницы,
sitemap и админ-эндпоинты объединены через query-роутинг (`api/pages.js?page=...`,
`api/admin-api.js` GET/POST) вместо одного файла на маршрут — иначе лимит превышался
(было 17, свели к 11).

### 2. Редизайн SEO-страниц под дизайн-систему лендинга

Первая версия SEO-страниц (шаг 1) была на отдельном минималистичном стиле —
пользователь потребовал вернуть визуальный язык `landing/index.html`
(Manrope, `--accent:#2f6bed`, карточки/hero/FAQ-аккордеон) и не терять
маркетинговые блоки ради тонкого SEO-контента. CSS лендинга вынесен в
`landing/shared.css` (+ копия в `/shared.css` для раздачи) и переиспользуется
и лендингом, и SEO-страницами через `api/_lib/seo-layout.js`.

Что в итоге на каждой SEO-странице (не только SEO-логика, а полноценные
маркетинговые блоки):
- hero (значок обновления → h1 → короткое `.lead`-описание → live-поиск
  адреса с подсказками из `/map/addresses.json` → count-up цифры реальной
  статистики);
- превью карты (`mapPreviewHtml`, browser-chrome + скриншот);
- «Текущие/Предстоящие отключения» — единый паттерн с группировкой,
  табами и overflow-плиткой (см. §1);
- блок «Как начать» (3 шага, живой мокап поиска/карточки/итога дня);
- trust-блок «Почему нам можно верить» — 4 AI-иллюстрации (OpenAI
  Images API, прозрачный фон, фирменный синий), без карточек-коробок
  (border-first — тонкая верхняя линия-разделитель, не border+shadow+плашка);
- анимированный блок «Сообщить о проблеме» (печатающийся текст, чек-анимация);
- FAQ в двухколоночном стиле (referenced: awesomic.com) — слева заголовок +
  sticky-карточка контакта, справа pill-строки на всю ширину с шевроном;
- финальный CTA с плавающими пинами.

**Грабли редизайна (не повторять):**
- `.rv`-элементы (scroll-reveal) требуют JS, который добавляет класс `.in`
  через IntersectionObserver — этот скрипт был скопирован из лендинга не
  сразу, без него все `.rv`-блоки оставались `opacity:0` невидимыми навсегда.
- Reveal-стаггер считался по ГЛОБАЛЬНОМУ индексу `.rv` по всему документу —
  у карточек далеко от начала страницы все делеи схлопывались в один
  максимум. Пересчитано по позиции СРЕДИ СОСЕДЕЙ (`parentElement`-relative).

## Свежие изменения (v23) — Supabase + админка + Decision Engine + ADS-платформа

Самое крупное изменение архитектуры с момента запуска: сервис перестал быть чисто
статическим (Vercel + Google Sheets) — появилась настоящая БД (Supabase/Postgres) и
полноценная админка. Три больших блока, все на проде и проверены сквозными тестами.

### 1. БД + админка (`/admin`, Basic Auth: логин `admin`)

Google Sheets больше не единственный способ управлять картой. Таблицы в Supabase:
`incidents`, `user_reports`, `incident_log` (schema.sql). Админка показывает список
incidents, даёт руками "Принудительно отключить/восстановить", фильтр по статусу,
удаление записей. Старые жалобы из Sheet импортированы в incidents (кнопка в админке).

### 2. Decision Engine — автоматическое подтверждение по жалобам жителей

Реализованы правила из отдельного тех.задания («BARJOK — автоматическая система
подтверждения отключений»): 3 уникальных жалобы с разных устройств (`actor_key` =
cookie `bj_device`) за rolling window (360 мин на отключение / 120 мин на
восстановление) → incident подтверждается сам, `confirmation_type=COMMUNITY`.
15-минутный cooldown защищает от дребезга статуса. `manual_override` в админке
имеет абсолютный приоритет — автоматика его не трогает, пока override не снят
(снятие сразу запускает переоценку, не дожидаясь следующей жалобы).
Модалка жалобы на карте (`map/index.html`/`app.js`) получила переключатель
«Всё ещё нет / Уже появилось» — раньше не было способа сообщить о восстановлении
через основную форму. `api/report.js` пишет в `user_reports` и гоняет Decision Engine
(`api/_lib/decision-engine.js`) параллельно со старой Telegram/Sheet-отправкой —
ничего из старого пайплайна не сломано.
Попутно нашли и починили баг: несколько incident'ов на один адрес+ресурс (старый
RESTORED + новый ACTIVE) — устаревший RESTORED глушил актуальный ACTIVE на карте.
Инцидент-адаптер (`parser/adapters/incidents.js`) теперь берёт только самый свежий
incident по паре адрес+ресурс.

### 3. ADS — своя рекламная платформа (`/admin/ads`)

Реализована по отдельному тех.заданию («BARJOK — ADS Management System»), в пять
последовательных фаз (так и разрабатывали — сначала data model, в конце UI/аналитика):

1. **Data model + campaign engine** — `advertisers/campaigns/creatives/placements/
   ads_events/ads_audit_log` (schema_ads.sql) + `api/_lib/ads-engine.js`: `selectAd()`
   реализует полную ротацию (active → schedule → targeting → exclusions → placement →
   frequency cap → лимиты показов/кликов → category exclusivity → priority/weighted
   rotation), `buildUtm()`/`appendUtmToUrl()` — UTM-билдер с макросами
   `{city}/{utility}/{placement}/{campaign_id}/{creative_id}` (БЕЗ `{address}` —
   адрес пользователя рекламодателю никогда не передаётся).
2. **UI создания кампании** — Advertisers/Campaigns/Creatives, Validate+Publish
   (errors блокируют публикацию, warnings — нет), Pause/Resume/Duplicate/Archive,
   UTM Preview с реальной ссылкой.
3. **Рендер на BARJOK** — нативный компонент (не баннер) в карточке дома
   (`outage_detail_context` — самый контекстный placement), обязательная подпись
   «Реклама» рекламодатель убрать не может. `api/ads-select.js` — публичный
   эндпоинт без admin-auth.
4. **Tracking** — `ad_rendered`/`ad_impression` (IntersectionObserver, ≥50% viewport
   ~1с)/`ad_click` пишутся в `ads_events` через `api/ads-track.js`. Замыкает цикл:
   frequency cap и лимиты показов/кликов из engine (фаза 1) наконец считают по
   реальным данным, а не по пустой таблице.
5. **Analytics + Reports** — Dashboard с KPI и алертами (кампания скоро закончится /
   нет активного creative), аналитика по кампании (impressions/reach/CTR/frequency/
   CPM/CPC, delivery/pacing, разбивка по creative), публичные read-only отчёты для
   рекламодателей по токену (`/report/:token`, `api/ads-report.js`) — опциональный
   пароль, срок действия, `disable_report`. Отчёт не показывает visitor_id/IP/точные
   адреса — только агрегаты.

Категории и placements — seed-данные на русском (`ads_categories`/`ads_placements`).
Вкладка в админке называется «ADS» (не «Реклама»).

⚠️ **Известное ограничение:** Billing/выставление счетов, графики по времени (сейчас
только числа и таблицы), RBAC-роли (пока один админ) — сознательно не в этой версии,
задел под них в схеме есть (permissions из документа, `pricing_model` в campaigns).

## Свежие изменения (v22) — поиск: не мешать RU/KZ варианты одной улицы

Пользователь: поиск «Естая 83» показывал одновременно «улица Естая, 83/1» (RU) и
«Естай көшесі, 83», «83/2», «83/3» (KZ) в одной выпадашке — путало.

**Причина:** `map/addresses.json` хранит одну и ту же физическую улицу ДВУМЯ отдельными
ключами — сырые `addr:street` из OSM/наших источников не дедуплицированы между RU- и
KZ-написанием («улица Естая» vs «Естай көшесі»). И `addressSuggestions()`, и
street/house-хиты в `buildSuggest()` (`map/app.js`) перебирали ВСЕ ключи без учёта языка.

**Фикс (`map/app.js`):** добавлены `streetLangOf(name)` (эвристика по казахским
суффиксам-типам көшесі/даңғылы/алаңы/тұйығы/шағын/ауданы и казахским буквам
әіңғұүқөһ) и `preferLang(items, nameOf)` — фильтрует список под текущий `LANG`, но
не даёт результату опустеть (если для улицы есть только один языковой вариант —
лучше показать его, чем скрыть адрес). Применено в `addressSuggestions()` (ceiling
поднят до `limit*6`, чтобы не оборвать перебор раньше, чем дойдём до нужного
языкового ключа) и в `streetHits`/`houseHits` внутри `buildSuggest()`.

Проверено в браузере: RU-режим + запрос «Естая 83» → только «улица Естая, 83/1».
KZ-режим + запрос «Естай 83» → только «Естай көшесі, 83 / 83/2 / 83/3», без RU-примеси.
Консоль без ошибок.

## Свежие изменения (v21) — «Восстановлено» через таблицу (убрать адрес с карты)

Пользователь: «хочу через таблицу помечать, что дом восстановили, чтобы он больше не
показывался отключённым». Новый модуль `parser/adapters/resolved.js`, подключён в
`pavlodar.js` **в самом конце**, после ВСЕХ источников (официальных + citizen + ручных) —
поэтому перекрывает отключение НЕЗАВИСИМО от того, откуда оно взялось.

**Механизм переиспользует существующую форму, без новых полей в Apps Script/таблице:**
- Вкладка **«Предложение»** (не «Жалоба») + указанный **адрес** + текст сообщения.
- Модератор ставит **`status=approved`** — это трактуется как «убрать отключение по
  адресу», а не как обычное предложение по сайту.
- Ресурс определяется по ключевым словам в тексте: «гор…» → hot_water, «холод…» →
  cold_water, «электр…/свет…» → electricity, «тепл…/отоплен…» → heating, «газ…» → gas.
  Если ключевых слов нет — убираются ВСЕ ресурсы по этому адресу (blanket).
- `doGet` в Apps Script менять не нужно — он уже отдаёт любые `approved`-строки без
  фильтра по `kind`.

⚠️ **Условие для модератора:** «Предложение» с заполненным адресом = сигнал восстановления.
Если одобряешь обычное предложение по сайту (не про конкретный дом) — оставляй адрес пустым,
иначе оно тоже попытается что-то убрать с карты по этому адресу.

⚠️ **Известное ограничение (не новое, давнее в проекте):** «улица Лермонтова» (русское
склонение) и «Лермонтов көшесі» (казахский/именительный вариант) дают РАЗНЫЕ ключи
нормализации улицы — восстановление может не сматчиться с записью другого источника,
если адрес набран другой формой написания одной и той же улицы. **Надёжнее всего** —
открывать форму «Сообщить о проблеме» **прямо из карточки дома** на карте (кнопка
автоподставляет точный адрес, `data-report-addr` в `map/app.js`) — тогда строки совпадут
дословно, и проблема нормализации не возникает.

Проверено на моке: точное совпадение адреса+ресурса убирается, другая улица/ресурс не
трогается, blanket-сброс без ключевых слов убирает все ресурсы адреса. На реальном фиде
пока 0 (тестовая строка «Лермонтова, 91, Дали горячую воду» ещё со `status=new`, не
одобрена — это ожидаемо, не баг).

## Свежие изменения (v18) — два бага доверия: «чужое отключение как своё» и Enter в поиске

- ⚠️ **«В карточке отключение есть, а пина на доме нет».** Это был НЕ баг рендера пинов.
  Пользователь кликал по дому, которого НЕТ в списке затронутых (напр. Айманова 9 — в данных

  **Фикс:** новая `sameAddress(a, b)` (улица через `streetMatches` + точное совпадение номера).
  Если точного адреса среди нарядов нет — заголовок честный: **«Рядом на этой улице: N систем»**

## Свежие изменения (v16) — ГВС по многоэтажкам (семантика здания, не геометрия)

**Проблема:** ПТС объявляет общегородские гидравлические испытания «в границах улиц/сетевого
района» (v13/v12 уже это фиксировали), но раньше размечались ТОЛЬКО явно названные улицы —
многоэтажки на неупомянутых улицах того же сетевого района не показывали отключение ГВС,
хотя оно у них реально есть (пользователь: «карта говорит есть, а по факту нет»).

**Почему не полигон (см. v7):** контур по геометрии улиц уже пробовали — 71% ложного
покрытия (Камзина/Малайсары уезжали за пределы города). **Решение — СЕМАНТИКА здания, не
площадь:** OSM хранит `building:levels`/`building=apartments|dormitory` у части домов.
Многоэтажки почти всегда на централизованном ГВС, частный сектор — нет. Это не даёт
искажения прошлой попытки (полигон), т.к. не зависит от геометрии улиц.

- `parser/lib/buildings.js`: Overpass-запрос дополнен этажностью/типом здания;
  `isMultiStory()` = `levels>=3` ИЛИ `building∈{apartments,dormitory}`. Формат кэша
  `[street,house,lat,lng,multi]` (было 4 поля → 5). Новая функция `allMultiStory()`.
  ⚠️ Кэш `buildings.json` **пересобран** (Overpass, ~40 тыс. домов, найдено **1015 известных
  многоэтажек** — частичное покрытие, OSM размечает этажность не у каждого здания).
- `pts-heat.js`: когда сегмент объявления помечен `isArea` («в границах улиц/районе»),
  дополнительно (union с именованными улицами) эмитятся ВСЕ известные многоэтажки на
  ОБЪЕДИНЁННЫЙ период всех isArea-сегментов ресурса (зоны Северный/Южный сетевой район
  OSM не различает → окно шире точной зоны, но не «ковёр на весь город» и не пусто).
  `reason` честно указывает на это ограничение.
- Итог: ГВС-адресов ~52 → **~1700** (наряды 1811). Проверено: фильтр «Горячая вода» на
  карте показывает конкретные многоэтажные дома (Сатпаева 11/13/15/17…).
- 🔜 Расширять покрытие = улучшать теги этажности в OSM (сторонний процесс) или получить
  точные зоны/списки домов от самой ПТС.

⚠️⚠️ **ГРАБЛИ: `git rebase` и `checkout --ours/--theirs` — семантика ОБРАТНАЯ относительно
merge.** При разрешении конфликта `map/data.json` во время `git rebase` я взял `--ours`,
ожидая «мою локальную версию» — но во время rebase `--ours` означает **upstream/remote**
(бот-коммит), а `--theirs` — коммит, который переносится (мой). Итог: код (`pts-heat.js`,
`buildings.js`) запушился верно, но реальный `map/data.json` откатился на старую логику
(hot_water 796/769 вместо 1811/1700) — данные не соответствовали задокументированному
изменению до следующего цикла бота. Нашли по прод-проверке (grep на новый `reason` в
запушенном файле), пересобрали, закоммитили отдельно (`f28c894`).
**Правило на будущее:** при конфликте `map/data.json` в rebase — НЕ полагаться на
`--ours`/`--theirs` по интуиции; либо перегенерировать файл заново (`node index.js pavlodar`)
после rebase и закоммитить, либо явно свериться, что взятая версия содержит ожидаемые
изменения (grep по новому полю/reason), прежде чем пушить.

  Аварийные — пунктиром. Клик по линии → карточка. Сейчас геометрия у 40 из 44 домов.
- **Фикс поиска (был сломан).** Раньше «Лермонтова 44» не находилось: поиск делал точное
  вхождение подстроки и был привязан к фильтру времени. Теперь:
  `parseQuery()` разбирает «улица + номер дома», `streetMatches()` сравнивает с учётом
  падежей/сокращений, а если адреса нет в данных — **геокодим через Nominatim** и показываем
  карточку «Отключений нет — вода и свет в порядке». Это и есть ответ сервиса.
- **Клик по любому дому.** `map.on('click')` → reverse-geocode → карточка адреса
  (с отключениями рядом или «отключений нет»). Раньше кликались только дома с отключениями.
- **Кэш-бастинг ассетов** (`?v=timestamp` у css/js) — иначе браузер держал старый `app.js`.
- ⚠️ **Язык карты.** Растровые тайлы CARTO содержат «вшитые» подписи на местном языке
  (в Павлодаре — казахский), поэтому при RU интерфейсе подписи остаются казахскими.
  Инфраструктура переключения готова (`setTiles(lang)`, `TILE_KEY`), но нужен провайдер
  с параметром языка — **MapTiler** (бесплатный ключ). Вставить ключ в `map/app.js` → `TILE_KEY`.
  Wikimedia `osm-intl` проверен — отдаёт 403 для внешних сайтов, использовать нельзя.

## Как обновить данные

```bash
node parser.js              # активный город (Павлодар)
node parser.js novosibirsk  # другой город из реестра
./parser/run.sh pavlodar    # то же + лог + защита от битых данных
```
Требуется системный `unzip` и сеть. Первый прогон геокодит улицы (~1.2 с/шт), дальше — кэш.

**Расписание — каждые 3 часа** (`StartInterval 10800`). Обоснование: источники обновляются
раз в сутки, но аварии могут выйти в любой момент; 3 ч = свежесть в пределах 3 ч при
минимальной нагрузке на чужие сайты. Реже — риск проспать аварию, чаще — бессмысленно.

```bash
cp parser/com.barjoq.parser.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.barjoq.parser.plist    # запустить
launchctl unload ~/Library/LaunchAgents/com.barjoq.parser.plist  # остановить
```
⚠️ LaunchAgent — только для локальной машины. Для прода — cron на VPS
(`0 */3 * * * /path/parser/run.sh pavlodar`) или GitHub Actions с коммитом `map/data.json`.

## Что НЕ трогать без понимания

- **`map/app.js` обёрнут в IIFE.** `data.js` объявляет глобальные `const` (`RESOURCES` и т.д.);
  без IIFE происходит `SyntaxError: Identifier already declared` и скрипт молча не выполняется.
- **Leaflet + размер контейнера.** Тайлы рисуются частично, если карта инициализируется до
  финального лэйаута. Лечится `ResizeObserver` + `invalidateSize()` — уже стоит, не удалять.
- **Версии ассетов `?v=`** в `map/index.html`. Без них браузер держит старый `app.js`.
  При правке css/js — бампнуть версию (или деплой на Vercel, там свои хеши).
- **Даты — «стенные» часы, записанные как UTC.** Форматирование через UTC-геттеры
  (`getUTCHours` и т.д.), иначе время поедет на часовой пояс зрителя.
- **`NOW` в адаптерах** = `process.env.BARJOQ_NOW ? Date.parse(...) : Date.now()` (v9).
  В проде — реальное время; для воспроизводимого теста пиновать `BARJOQ_NOW=2026-08-03T12:00:00Z`.
  ⚠️ Не возвращать зашитую дату — иначе live-cron будет фильтровать отключения относительно неё.
- **Демо-данные (`pavlodar-curated.js`)** — только аварийный фолбэк. Не домешивать к реальным:
  из-за этого карта один раз показывала выдуманные аварии.
- **`parser/buildings.json` (2.6 МБ) не в git** — качается один раз с Overpass при первом
  запуске парсера. Пересоздать: удалить файл или `node -e "require('./parser/lib/buildings').refresh()"`.
- **GL-подложка:** не трогать z-index контейнера и не убирать ресайз после монтирования
  (см. v6) — иначе карта белая.
- **`\b` в регулярках по кириллице не работает.** Границы слов задавать явно.
- **🔑 СЕКРЕТЫ — только в env, НИКОГДА в код/git** (репозиторий публичный): `TELEGRAM_BOT_TOKEN`,
  `TELEGRAM_CHAT_ID`, `SHEET_WEBHOOK_URL` (Vercel), `CITIZEN_FEED_URL` (GitHub Actions Variables).
  `api/report.js` и `citizen.js` читают их из `process.env`. Если засветился — перевыпустить у @BotFather.
- **Жалобы жителей на карте — ТОЛЬКО после модерации** (`status=approved` в таблице). Не пускать сырой
  пользовательский ввод в ленту — нарушит 🔒-правило «только официальные источники» и XSS. Текст жителя
  санитизируется в `citizen.js` (срез тегов) + фронт эскейпит (`esc()` в app.js) — не убирать.
- **Мобильная шторка карты:** `touch-action` — шапка `none` (драг), список `pan-y` (скролл). Вернуть
  `touch-action:none` на всю `.sheet` НЕЛЬЗЯ — список перестанет прокручиваться (был баг).
- **CSP пока НЕ включён** намеренно: maplibre создаёт blob-воркеры/WebGL, неверный CSP → белая карта.
  Включать только с проверкой на превью Vercel (TODO).
- **`api/report.js`** — serverless-функция Vercel (`/api/*`). `trailingSlash:true` в `vercel.json` её не ломает
  (POST на `/api/report` работает). Не переносить токен в клиентский JS.

## Деплой (Vercel) — РАБОТАЕТ

**Прод: https://barjok.vercel.app** — деплоится автоматически на каждый `git push` в `main`.

Настройки проекта: Framework Preset **Other**, Root Directory `./`, Build Command и
Output Directory — **пустые** (чистая статика, маршруты из `vercel.json`).
Домен `barjoq.kz` подключается в Vercel → Settings → Domains.

### ⚠️ Грабли деплоя (были 404 — не повторять)

1. **`cleanUrls: true` ломает rewrites.** Он делает `/landing/index.html` доступным как
   `/landing`, и destination рерайта перестаёт резолвиться → 404 на `/`. **Не включать.**
2. **Rewrite на директорию ломает относительные ассеты.** Было
   `{"source":"/map","destination":"/map/index.html"}` — URL в браузере оставался `/map`
   (без слэша), поэтому `styles.css` резолвился в `/styles.css` → 404, карта грузилась
   голой (гигантские SVG без CSS).
   **Решение:** `"trailingSlash": true` + **никакого рерайта на `/map`** — Vercel сам
   отдаёт `map/index.html` для `/map/`, и относительные пути работают.
   Ссылки на карту вести как `/map/` (со слэшем).
3. Рерайты нужны только там, где путь ≠ папке: `/` → `landing/index.html`, `/ads` → `landing/ads.html`.

Итог `vercel.json`: `trailingSlash: true` + 3 рерайта (`/`, `/ads`, `/ads/`) + cache-заголовок
для `map/data.json`.

✅ Данные на проде обновляются сами: `.github/workflows/parser.yml` (cron каждые 3 ч) прогоняет
парсер и коммитит `map/data.json` в репозиторий → Vercel редеплоит на push. Подробнее — раздел v9.
